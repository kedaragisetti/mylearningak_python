# 4.1 Functions

## 4.1.1 Why Do We Need Functions?

### What & Why

Copying and pasting the same block of code in multiple places creates maintenance nightmares—if you fix a bug in one spot, you have to hunt down every copy. **Functions** bundle reusable logic under a single name (the **DRY** principle: *Don't Repeat Yourself*).

### Example

```python
def prompt_number():
    print("Enter a value: ")

prompt_number()
a = int(input())
prompt_number()
b = int(input())
```

---

## 4.1.2 Decomposition

### What & Why

**Decomposition** means breaking a large, intimidating problem into small, independent functions where each function handles one clear job. Small functions are easier to write, read, and test in isolation.

---

## 4.1.3 Where Do the Functions Come From?

### What & Why

Python functions come from three sources:
1. **Built-in functions:** Ready out of the box (`print()`, `len()`, `input()`, `int()`).
2. **Standard library modules:** Pre-installed toolkits you import (`math.sqrt()`, `random.randint()`).
3. **User-defined functions:** Custom functions you write yourself using `def`.

---

## 4.1.4 Your First Function

### What & Why

You create a function using the `def` keyword, followed by the function name, parentheses, and a colon. Everything indented underneath forms the function body.

### Key Mechanics & Gotchas

- Function names follow the same rules as variable names (letters, digits, underscores; cannot start with a digit; `snake_case` by convention).
- An empty body is a `SyntaxError`—use `pass` as a placeholder while drafting.

### Example

```python
def greet():
    print("Hello from inside the function!")

greet()

# Output:
# Hello from inside the function!
```

---

## 4.1.5 How Functions Work

### What & Why

When Python sees `def`, it memorizes the function without running it yet. When you **invoke** (call) `my_func()`, Python jumps into the function, runs every line inside, and jumps right back to where it left off.

### Key Mechanics & Gotchas

- **Define before calling:** Calling a function above its `def` raises a `NameError`.
- **No name collisions:** Never give a variable the exact same name as your function—assigning `greet = 5` overwrites the function reference and breaks future calls.

### Example

```python
print("Start")

def message():
    print("Inside message()")

message()
print("End")

# Output:
# Start
# Inside message()
# End
```

# 4.2 How Functions Communicate With Their Environment

## 4.2.1 Parameterized Functions

### What & Why

Parameters turn functions from rigid scripts into flexible tools that accept input data.

### Key Mechanics & Gotchas

- **Parameter:** The variable listed inside the parentheses in `def my_func(x):` (lives only inside the function).
- **Argument:** The actual value passed when calling `my_func(10)`.

### Example

```python
def greet_user(name):
    print("Welcome,", name)

greet_user("Ada")
greet_user("Linus")

# Output:
# Welcome, Ada
# Welcome, Linus
```

---

## 4.2.2 Positional Parameter Passing

### What & Why

By default, Python matches arguments to parameters strictly by their left-to-right order.

### Example

```python
def introduce(first_name, last_name):
    print("Hello, my name is", first_name, last_name)

introduce("Luke", "Skywalker")
introduce("Skywalker", "Luke")

# Output:
# Hello, my name is Luke Skywalker
# Hello, my name is Skywalker Luke
```

---

## 4.2.3 Keyword Argument Passing

### What & Why

Keyword arguments label each value with `parameter_name=value` during the call, so order no longer matters.

### Example

```python
def introduce(first_name, last_name):
    print("Hello, my name is", first_name, last_name)

introduce(last_name="Skywalker", first_name="Luke")

# Output:
# Hello, my name is Luke Skywalker
```

---

## 4.2.4 Mixing Positional and Keyword Arguments

### What & Why

You can combine both styles in a single function call, provided you follow one strict rule.

### Key Mechanics & Gotchas

- **The Golden Rule:** **Positional arguments MUST come before keyword arguments.** Putting a positional argument after a keyword argument raises a `SyntaxError`.
- Never pass two values for the same parameter (e.g., `add(1, a=2)` causes a `TypeError`).

### Example

```python
def adding(a, b, c):
    print(a, "+", b, "+", c, "=", a + b + c)

adding(1, c=3, b=2)

# Output:
# 1 + 2 + 3 = 6
```

---

## 4.2.5 Parametrized Functions – More Details

### What & Why

You can give parameters **default values** in the `def` header so callers can omit optional arguments.

### Key Mechanics & Gotchas

- Parameters with default values must be placed **after** all required (non-default) parameters.

### Example

```python
def introduce(first_name, last_name="Smith"):
    print("Hello, my name is", first_name, last_name)

introduce("Jane")
introduce("Jane", "Doe")

# Output:
# Hello, my name is Jane Smith
# Hello, my name is Jane Doe
```

# 4.3 Returning a Result From a Function

## 4.3.1 Effects and Results: The `return` Instruction

### What & Why

Functions can produce an **effect** (like printing to the screen) or return a **result** back to the caller using `return`.

### Key Mechanics & Gotchas

- `return` immediately exits the function—any lines below it in the same block are unreachable.
- `return` with no value exits early and sends back `None`.

### Example

```python
def happy_new_year(wishes=True):
    print("Three...")
    print("Two...")
    print("One...")
    if not wishes:
        return
    print("Happy New Year!")

happy_new_year(False)

# Output:
# Three...
# Two...
# One...
```

---

## 4.3.2 A Few Words About `None`

### What & Why

`None` is Python's special object representing "nothing" or the absence of a value.

### Key Mechanics & Gotchas

- Any function without a `return` statement automatically returns `None`.
- Always check for `None` using identity operators: `if result is None:` or `if result is not None:`.
- You cannot perform arithmetic on `None` (`None + 1` raises a `TypeError`).

### Example

```python
def check_even(n):
    if n % 2 == 0:
        return True

print(check_even(4))
print(check_even(5))

# Output:
# True
# None
```

---

## 4.3.3 Effects and Results: Lists and Functions

### What & Why

Lists can be passed into functions as arguments and returned from functions just like numbers or strings.

### Example

```python
def create_even_list(n):
    evens = []
    for i in range(n):
        if i % 2 == 0:
            evens.append(i)
    return evens

print(create_even_list(10))

# Output:
# [0, 2, 4, 6, 8]
```

## 4.3.4 LAB – A Leap Year: Writing Your Own Functions

### Core Logic

A Gregorian leap year is divisible by `4`, **except** century years (`% 100 == 0`) which must also be divisible by `400`.

### Solution

```python
def is_year_leap(year):
    if year % 4 != 0:
        return False
    elif year % 100 != 0:
        return True
    elif year % 400 != 0:
        return False
    else:
        return True

print(is_year_leap(1900))
print(is_year_leap(2000))
print(is_year_leap(2016))

# Output:
# False
# True
# True
```

## 4.3.5 LAB – How Many Days: Writing and Using Your Own Functions

### Core Logic

Reuse `is_year_leap(year)` to return `29` for February in leap years (`28` otherwise), `30` for April/June/September/November, and `31` for the rest. Return `None` for invalid inputs.

### Solution

```python
def days_in_month(year, month):
    if year < 1582 or month < 1 or month > 12:
        return None
    days = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]
    if month == 2 and is_year_leap(year):
        return 29
    return days[month - 1]

print(days_in_month(2000, 2))
print(days_in_month(1900, 2))
print(days_in_month(2026, 11))

# Output:
# 29
# 28
# 30
```

## 4.3.6 LAB – Day of the Year: Writing and Using Your Own Functions

### Core Logic

Validate the date first using `days_in_month(year, month)`. Then sum the days of all completed preceding months and add `day`.

### Solution

```python
def day_of_year(year, month, day):
    max_days = days_in_month(year, month)
    if max_days is None or day < 1 or day > max_days:
        return None
    total_days = 0
    for m in range(1, month):
        total_days += days_in_month(year, m)
    return total_days + day

print(day_of_year(2000, 12, 31))
print(day_of_year(2026, 3, 1))

# Output:
# 366
# 60
```

## 4.3.7 LAB – Prime Numbers – How to Find Them

### Core Logic

Numbers less than `2` are not prime. Otherwise, check divisibility from `2` up to $\sqrt{\text{num}}$ (`int(num ** 0.5) + 1`). If any divisor divides evenly, it's not prime.

### Solution

```python
def is_prime(num):
    if num < 2:
        return False
    for i in range(2, int(num ** 0.5) + 1):
        if num % i == 0:
            return False
    return True

for i in range(1, 20):
    if is_prime(i + 1):
        print(i + 1, end=" ")
print()

# Output:
# 2 3 5 7 11 13 17 19
```

## 4.3.8 LAB – Converting Fuel Consumption

### Core Logic

Convert between European **liters per 100 km** and American **miles per gallon** using exact conversion constants:
- `1 mile = 1609.344 meters` (`1.609344 km`)
- `1 gallon = 3.785411784 liters`

### Solution

```python
def liters_100km_to_miles_gallon(liters):
    gallons = liters / 3.785411784
    miles = 100 * 1000 / 1609.344
    return miles / gallons

def miles_gallon_to_liters_100km(miles):
    km = miles * 1609.344 / 1000
    liters = 3.785411784
    return (liters / km) * 100

print(round(liters_100km_to_miles_gallon(3.9), 2))
print(round(miles_gallon_to_liters_100km(60.3), 2))

# Output:
# 60.31
# 3.9
```
