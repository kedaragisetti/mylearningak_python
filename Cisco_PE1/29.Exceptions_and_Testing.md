# 4.7 Exceptions

## 4.7.1 Errors – The Developer's Daily Bread

### What & Why

Errors fall into two main buckets:
1. **Syntax errors:** Typos in Python grammar caught *before* the program even starts running.
2. **Exceptions:** Runtime crashes that occur while executing valid syntax (e.g., dividing by zero or opening a missing file).

---

## 4.7.2 When Data Is Not What It Should Be

### What & Why

Users will inevitably type `"abc"` when asked for an integer or enter `0` as a divisor. Without protection, Python terminates the program and prints a traceback.

---

## 4.7.3 The `try-except` Branch

### What & Why

Wrapping risky code inside a `try` block lets you catch errors gracefully in an `except` block instead of letting your program crash.

### Example

```python
try:
    value = int(input("Enter a natural number: "))
    print("The reciprocal of", value, "is", 1 / value)
except:
    print("I do not know what to do.")
```

---

## 4.7.4 The Exception Proves the Rule

### What & Why

Inside a `try` block, the moment an exception occurs, Python **immediately aborts** the remaining lines in `try` and jumps straight to the matching `except` branch. If no error happens, `except` is skipped completely.

---

## 4.7.5 How to Deal With More Than One Exception

### What & Why

Different failures require different user feedback. You can stack multiple named `except` branches after a single `try`.

### Key Mechanics & Gotchas

- Python checks `except` blocks from top to bottom and runs **at most one** matching branch.
- Always list **more specific exceptions before general ones** (e.g., `ZeroDivisionError` before `ArithmeticError` or `Exception`).

### Example

```python
try:
    value = int(input("Enter a natural number: "))
    print("The reciprocal of", value, "is", 1 / value)
except ValueError:
    print("Please enter a valid integer.")
except ZeroDivisionError:
    print("Division by zero is not allowed.")
```

---

## 4.7.6 The Default Exception and How to Use It

### What & Why

A bare `except:` (with no exception name) acts as a catch-all safety net for any unexpected error.

### Key Mechanics & Gotchas

- A bare `except:` **must always be the very last branch**—placing any named `except` after it causes a `SyntaxError`.

### Example

```python
try:
    x = int("hello")
except ValueError:
    print("Invalid number format.")
except:
    print("Something else went wrong.")

# Output:
# Invalid number format.
```

---

## 4.7.7 Some Useful Exceptions

| Exception | When It Happens |
| :--- | :--- |
| `ZeroDivisionError` | Dividing or taking modulo by `0` (`5 / 0`, `5 // 0`, `5 % 0`) |
| `ValueError` | Right data type, inappropriate value (`int("abc")`) |
| `TypeError` | Wrong data type for an operation (`"age: " + 25`, `len(5)`) |
| `AttributeError` | Calling a non-existent method/attribute (`(1, 2).append(3)`) |
| `SyntaxError` | Invalid Python syntax (caught before execution; cannot be caught in the same file's `try`) |

---

## 4.7.8 Why You Can't Avoid Testing Your Code

### What & Why

Code that runs without crashing isn't automatically bug-free. Testing verifies that every branch and edge case behaves as intended before users encounter it.

---

## 4.7.9 When Python Closes Its Eyes

### What & Why

**Logical (semantic) bugs** occur when your code is 100% valid Python and produces no exceptions, yet calculates the wrong answer (e.g., writing `a + b / 2` instead of `(a + b) / 2`). Python cannot detect these—only careful testing will.

---

## 4.7.10 Tests, Testing, and Testers

### What & Why

Good testing exercises every code path, not just the "happy path":
- Test normal inputs, boundary values (`0`, `-1`, empty lists), and invalid types.
- Ensure every `if` / `elif` / `else` branch executes at least once.

---

## 4.7.11 `print` Debugging

### What & Why

Inserting temporary `print()` calls before and after suspicious operations lets you watch variables change in real time. Just remember to remove or comment them out once the bug is fixed.

### Example

```python
def calculate_discount(price, discount_pct):
    # print("DEBUG inputs:", price, discount_pct)
    final_price = price * (1 - discount_pct / 100)
    return final_price
```

---

## 4.7.12 Some Useful Tips

- **Read tracebacks bottom-up:** The last line tells you *what* exception occurred; the line right above it shows *where* it happened.
- **Change one thing at a time:** Test after each small fix so you know what actually solved the issue.
- **Explain your code out loud (Rubber Duck Debugging):** Walking through logic line by line exposes hidden assumptions immediately.

---

## 4.7.13 Unit Testing – A Higher Level of Coding

### What & Why

**Unit testing** automates verification by writing small, repeatable tests that check each individual function against expected outputs (using Python's `unittest` module or `assert` statements). Whenever you refactor code later, running your unit tests instantly confirms nothing broke.

### Example

```python
def add(a, b):
    return a + b

# Simple automated checks:
assert add(2, 3) == 5
assert add(-1, 1) == 0
print("All unit checks passed!")

# Output:
# All unit checks passed!
```
